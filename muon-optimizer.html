Muon 是 2024 年末由 Katherine Lee 与 Tri Dao（KDL）提出的优化器，专为 LLM 的隐层（矩阵权重）设计。它的核心是「动量 + 正交化」：把动量梯度用 Newton-Schulz 迭代正交化成一个旋转矩阵，再走一个固定大小的步。在 LLM 训练上，Muon 用明显更少的 token 就能达到和 AdamW 相同的 loss，而且常常更快、更稳、对超参更不敏感。这篇博客讲透 Muon 的算法直觉，并和 AdamW 逐维度对比。

一、背景：AdamW 的「逐参数归一化」在做什么

AdamW 每一步干两件事：

  • 用一阶矩 m、二阶矩 v 分别估计梯度的均值与方差；
  • 用 1/√v 对每个参数元素做逐元素归一化，再乘学习率。

这套机制极其通用——标量、向量、矩阵一视同仁，每个元素独立处理。但它隐含一个假设：每个参数彼此独立，方向由自身梯度决定、幅值由自身历史方差缩放。对隐层这种矩阵参数，这个假设有点「歪」：一个矩阵的梯度方向应该作为一个整体（一个线性映射）来理解，而不是被拆成一堆孤立元素。逐元素归一化会把矩阵的几何结构打散。

二、核心直觉：把每个方向的更新幅度拉平

AdamW 的逐参数归一化对标量是中性的，但对矩阵有一个不舒服的性质：每个参数走一步的步长与它自身梯度的滑动均值大小成正比。而隐层的梯度动量往往近似低秩——能量挤在少数几个奇异方向上，那几个大方向主导了更新，很多幅度小但重要的方向几乎得不到更新，收敛就慢。

隐层权重 W 本质上是一个线性映射。对一个线性映射做「最自然的更新」，不是把每个元素各自推一点，而是乘上一个正交矩阵（一个旋转）。正交化把每个方向的更新幅度拉平：既不因某方向梯度大就猛推，也不因某方向梯度小就无视。小而重要的方向终于被重视，同时大方向也不会失控放大。

Muon 的做法就是把梯度（动量之后的梯度）正交化成纯旋转，然后走一个固定大小的步。于是：

  • 每步更新幅度恒定（正交矩阵范数是 √rank，再乘固定系数），不随梯度幅值波动；
  • 更新方向是梯度的「正交方向」，保留了矩阵的几何意义。

这就是 Muon 名字里的 M（Momentum）和 O（Orthogonalize）。

4. 1D 参数回退 AdamW

Muon 只对 2D 矩阵有意义。对 bias、LayerNorm、embedding、输出头等 1D 参数，直接回退 AdamW。所以实践里 Muon 是个 hybrid 优化器：矩阵参数用 Muon，1D 参数用 AdamW。

四、为什么 Muon 更快、更稳

步长恒定，不浪费步数。 Adam 的逐元素归一化在方差大的参数上会把步长压得很小，大量步几乎原地踏步。Muon 的旋转步大小恒定，每一步都有有效进展。

matmul 比 elementwise 更省。 AdamW 是逐元素操作（读 m、v、p 再写回），是内存带宽瓶颈；Muon 的正交化是几次矩阵乘，是计算瓶颈，而现代 GPU 对 matmul 的优化极好。在合适的矩阵形状下，Muon 的 wall-clock 常常反而比 AdamW 快。

对超参鲁棒、基本免 warmup。 步长是固定旋转，Muon 对学习率没那么敏感，也不需要 Adam 那样一段很长的 warmup 去等二阶矩估计稳定。

显存更省。 Muon 只需存动量缓冲 m（与 AdamW 一阶矩同量级），不用存二阶矩 v，自适应状态直接省一半。

五、Muon vs AdamW 逐维度对比

维度AdamWMuon
归一化粒度逐参数（每元素独立）矩阵级（整个隐层一起正交化）
步长行为自适应，可缩到极小（随 1/√v）固定，恒定旋转（不随梯度幅值变）
几何保真逐元素归一化会扭曲矩阵方向正交化保留矩阵的旋转几何
计算开销O(n) 逐元素，内存带宽瓶颈O(n³) 矩阵乘，计算瓶颈（常数小、GPU 高效）
收敛速度基线更少 token 达相同 loss（KDL 实验约 2 倍量级加速）
适用形状任意（标量 / 向量 / 矩阵）仅 2D 矩阵；1D 回退 AdamW
超参敏感度较敏感，需要 warmup较鲁棒，基本免 warmup
显存自适应状态m + v 两份仅 m 一份
实现复杂度简单、标准需 Newton-Schulz 迭代 + 缩放标定

六、实验结果（KDL 原文）

KDL 在训练约 1.4B 参数、Llama 风格架构的 LLM 上对比了 Muon、AdamW 与 AdamW-8bit。结论：Muon 用显著更少的 token 达到相同验证 loss（大致 2 倍量级加速），训练曲线更平滑、对 LR 选择更宽容。注意优势主要在「大量隐层矩阵」的 LLM 上——矩阵参数占比越高，Muon 收益越明显；纯 1D 或非矩阵模型里没有用武之地。

七、分布式训练：Muon 唯一的额外代价

Muon 的正交化需要完整的梯度矩阵才能做，没法像 AdamW 那样逐元素直接分片到不同 GPU。论文里的 Distributed Muon 在数据并行组里先 Gather 出完整梯度、算完正交化再把各自那部分取回本地，通信开销大约只比 AdamW 高 1 ~ 1.25 倍——在万亿参数这种通信本来就昂贵的场景下基本可忽略。

八、实践要点与坑

  • Hybrid 用法：矩阵参数走 Muon，1D 参数走 AdamW。别对 bias / embedding 套 Muon。
  • 迭代次数：5 次 Newton-Schulz 是经验值——太少不收敛（不正交），太多纯浪费。
  • 缩放系数：mu_scale 是标定值，换矩阵形状或 batch 规模可能要重调。
  • 显存：比 AdamW 省一份二阶矩 v；动量缓冲 m 与 AdamW 一阶矩相当。
  • 别指望 Muon 全替代 AdamW：它只优化矩阵参数，非矩阵部分仍归 AdamW。
  • 固定步长 = 不会自动刹车：损失面特别陡的地方，Muon 可能不如 AdamW 收敛得细腻，需配合合适的 LR。
  • Kimi K2 已经验证：月之暗面 Kimi K2 在万亿参数规模上就用 Muon 的改进版 MuonClip 端到端训练，是第一个不依赖 AdamW 的开源大模型——MuonClip 把正交化步长做了更细的截断控制，更稳。

九、结论

Muon 把「隐层是线性映射」用进了优化器：不逐参数归一化，而是把梯度正交化成旋转、走固定步长。它与 AdamW 不是竞争关系，而是分工——矩阵参数用 Muon，1D 参数用 AdamW。在 LLM 训练上 Muon 能少用约一半 token 达到同等效果，还更稳、更省显存、更不挑超参。如果你在训 LLM、受困于 AdamW 的收敛慢或对 LR 敏感，Muon 值得上手一试。
