不堆深度，而是循环。这是 Apple 和 Amazon 的 Loop Transformer 论文（arXiv:2410.13826）的核心思路。一个 Transformer block，反复执行 N 次，每次执行时通过一组循环参数和记忆向量读取并更新状态。效果是：用远少于标准 Transformer 的参数量，达到同等或更好的性能，同时把推理的计算量摊到 N 次循环里。

一个 block，循环 N 次

标准 Transformer 的推理是：输入 → Block₁ → Block₂ → … → Block_L → 输出。L 层固定堆叠，每层参数独立，显存占用随 L 线性增长。

Loop Transformer 的做法：只有一个（或少数几个）block，把它循环执行 N 次。每次循环时，block 读取一组循环参数（loop parameters）和记忆向量（memory vector），更新内部状态，输出给下一次循环。N 次循环后得到最终表示。

这相当于把标准 Transformer 的深度轴从空间（堆叠的层）换成了时间（循环的次数）。同一个 block 的权重被复用 N 次，而循环参数和记忆向量充当跨循环的状态载体。

循环参数：每次循环都不一样

如果 N 次循环用的是完全相同的参数，整个结构退化成同一个函数调用 N 次，表达能力受限。Loop Transformer 给每次循环配了一组专属的循环参数。

这些参数不是完整的 block 权重（那样就等价于 N 个独立 block 了），而是轻量级的调制参数：缩放、门控、偏置等。记忆向量则是一个固定大小的向量，在每次循环中被更新，充当循环间的记忆总线。

这样，N 次循环的每个迭代都略有不同，但共享绝大部分权重。参数量 ≈ 1 个 block + N 组轻量参数，远小于 N 个独立 block。

参数与计算对比

设标准 Transformer 有 L 层，每层参数量 P。Loop Transformer 有 N 次循环，每次循环用 1 个 block（参数量 B）和一组循环参数（参数量 P_loop，通常远小于 P）：

维度标准 Transformer（L 层）Loop Transformer（N 次循环）
参数量L × PB + N × P_loop（P_loop ≪ P）
推理计算量L 次 forward，顺序执行N 次循环 forward，顺序执行（有状态依赖）
显存占用（推理）L 份权重1 份 block 权重 + N 份轻量循环参数
训练梯度直接反向传播，L 层各存激活循环展开 N 次再反向展开（BPTT）

关键：Loop Transformer 的参数量几乎不随 N 增长（循环参数很轻量），而推理计算量随 N 线性增长。可以用更少的参数换取更多的深度计算——在参数受限的场景（移动端、端侧推理）尤其有价值。

训练：展开，反向也展开

训练时需要把 N 次循环循环展开（unroll）成 N 个串联的 block，然后对展开后的计算图做反向传播。梯度通过 N 次循环传播，机制和 RNN 的 BPTT 相同。

反向传播时，PyTorch/TF 的 autograd 沿着展开的计算图逐循环回传梯度，每个循环的 block 权重接收来自后续所有循环的梯度之和。这和 RNN 的 BPTT 是同一套机制。

训练时 N 次循环的激活都要保存，显存占用 ≈ N 份激活 + 1 份 block 权重。推理时只需 1 份 block 权重 + N 份轻量循环参数，显存大幅低于标准 L 层 Transformer。

循环混合：RNN 与 Transformer 的桥

Loop Transformer 的结构其实是 RNN 和 Transformer 的循环混合——一个每步执行一个 Transformer block 的 RNN。这和 Hyper-Transformer、Recurrence Transformer、DeepNet 的思路是同一族。

DeepNet（arXiv:2402.02940）用 Hyper-Connections 替代固定残差连接，让每一层通过可学习的路由动态聚合前序所有层的输出。Loop Transformer 的循环参数可以看作 Hyper-Connections 的循环版：循环参数决定每次循环如何调制 block 的行为。

从 RNN 视角看，Loop Transformer 是一个每步做完整 attention + FFN 的 RNN。从 Transformer 视角看，它是一个深度为 N 的 Transformer，但所有层共享权重、只保留循环参数。这个双重身份让它同时受益于 RNN 的权重共享和 Transformer 的表达力。

局限与适用场景

循环展开训练需要 N 份激活，训练显存随 N 增长，和标准 L 层 Transformer 一样。推理显存虽低，但 N 次循环有状态依赖，只能顺序执行，推理延迟随 N 线性增长。这使得 Loop Transformer 更适合参数受限但计算不敏感的场景：端侧推理、小模型部署、参数预算紧张但算力充足的环境。

对于大规模高吞吐推理，N 次循环的顺序执行是硬伤。这是它和标准 Transformer 最核心的 trade-off。
