LLM 的自回归范式正在生产环境里露出疲态：答案不稳定、要解析输出文本、成本和延迟都压在关键路径上。Nace.AI（Nischay Dhankhar、Alisher Amantay、Zhanibek Datbayev）这篇技术报告给出了另一条路——决策模型（decision model）：给定一个状态和一组用户提供的选项，模型不做任何自回归解码，直接返回这组选项上的概率分布。最大型号 Drex Max 在真实数据决策上与前沿模型打平，单请求中位延迟 183ms，而 GPT-6 Sol 约 2 秒、Claude Opus 5.5 约 3.5 秒。四个模型全部开源。大模型加速优化全景图里梳理了训练加速与推理加速的八大板块，决策模型是这条线上「输出形态」维度的一个极端样本。

核心要点

  • 不生成、不解码：决策模型对用户在请求里给定的选项集直接返回概率分布，绕开自回归解码，单请求中位延迟 183ms，约为 GPT-6 Sol 的 1/11、Claude Opus 5.5 的 1/19。
  • 四种基座、一个接口：8B 扩散 LM、9B DeltaNet 混合、35B-A3B MoE、27B 稠密多模态——前三者用指针头共享缓存，Max 用双向注意力加读出头换更高精度。
  • RLAF 比 GRPO 更适合校准敏感任务：用恰当评分规则做奖励加 KL 正则到 SFT 策略，把准确率与校准同时激励，消融里 Decision Index +2.0 分、ECE 降 0.9 个百分点。
  • 顺序鲁棒性是损失项不是事后测量：置换一致性项把选项翻转率从 6.3% 压到 4.2%，准确率几乎不变。

一、什么是决策模型

把输入映射到固定集合的任务，历来有三种做法：编码器模型在最后层挂一个分类头；T5 把标签当字符串生成；解码器模型靠 prompt 让它吐出标签。这三种方案的共同点是输出形状在部署前就固定了——分类头在训练时定死标签，重排器每个候选返回一个数，嵌入模型每个输入返回一个向量。

决策模型关心的是另一种设定：候选输出集合随输入变化。用户在请求里给定上下文（状态）、问题，以及这次要选的选项列表；模型对每个选项给出一个概率。自回归模型做这件事有两条路：要么 prompt 它生成答案再解析文本，要么用约束生成把解码限制在允许的字符串上。第二条路能保证输出合法，但模型并不是被训练来预测「选项集合上的分布」的，约束生成还要逐步重归一化，选项共享前缀或长度不同时，结果和模型对整个字符串的偏好并不一致；逐选项打分再加总归一，则每个选项都要跑一次前向。

Drex 的做法是一种新的读出方式：选项集合在推理时由用户给出，模型对每个选项直接输出概率。这就是报告里说的 System One 接口——请求是一个元组 (S, I, {q_k})：S 是状态（文本或渲染成缩进文本的 JSON），I 是可选的图像集合，每个问题 q_k 带类型（choice 多选一、noul 是非题、score 有序量表打分）、指令和至多 255 个选项的有序列表。模型对每个问题返回一个概率分布 p_k。

一个接口，四个基座

Drex 家族有四个模型，共享同一个接口和同一份训练数据底座，但分别建在四种完全不同的基座上：

模型参数量基座读出方式
Drex DLM8B扩散语言模型，状态段内双向注意力指针头（pointer head）
Drex v1.59BGated DeltaNet 混合模型指针头
Drex v2.035B（激活 3B）稀疏 MoE（Qwen3.6-35B-A3B）指针头
Drex Max27B稠密多模态（Qwen3.8-27B）读出头（readout head）

三个指针模型（DLM、v1.5、v2.0）把上下文编码一次，在所有问题间共享这份编码，降低成本和延迟；Drex Max 则对每个问题重新编码上下文，用稠密多模态基座加双向注意力换取更高精度。这是整篇报告的核心对照。

二、创新点

指针架构：上下文编码一次，所有问题共享

请求被打包成一条 token 序列：状态段 S 之后接每个问题一个 question block（指令、选项、一个 <decide> 收尾 token，每个选项用 <opt>...</opt> 标签围住）。注意力掩码是 block-causal：问题块内的 token 能看状态的全部 token 和自身块内前序 token，但看不到其它问题块。于是 p_k 只依赖状态和问题 k，与同请求里其它问题怎么排、怎么增删无关，状态编码还能缓存复用。

指针头本身极小：取 <decide> 处的隐状态经 W_q 得到查询 q，取每个 </opt> 处的隐状态经 W_k 得到键 k_j，打分是缩放点积 z_{k,j} = k_j^T q / √d_p，softmax 之后就是该问题的选项分布。d_p = 256，v1.5（d=4096）整个指针头只有 210 万参数，v2.0（d=2048）只有 100 万，不到基座的 0.03%。三个选项的问题和 150 个选项的问题用同一个头，训练时没见过的选项也走同一套打分机制。推理时不需要任何解码。

v1.5 与 v2.0 的基座是 Gated DeltaNet 混合模型——线性注意力与全局注意力层交错。线性注意力把上下文压成固定大小的递归状态，省显存但状态更新是推理瓶颈，递归态量化（LeapQuant）那条线上的工作正好和它互补。

RLAF：用恰当评分规则做奖励

监督训练的标签是 one-hot，诚实的答案其实往往有不确定性，one-hot 会训练出过度自信。RLAF（reinforcement learning from adjusted feedback）的做法是给每个问题构造一个调整后的目标分布 q̃：先由教师模型给出选项分布，再用已验证的结果 y*（金标、执行结果或游戏引擎输出）去调整，使目标分布与已知事实一致，同时保留教师在其余选项上的不确定性。奖励是一个恰当评分规则（proper scoring rule）——当结果从 q̃ 采样时，期望奖励在 p = q̃ 处取最大。报告用的是对数似然加球面距离项，score 问题再减去平方 Cramér 距离（即 ranked probability score）。

因为每一项都是恰当评分规则，期望奖励恰好在 p = q̃ 处最大，所以准确性与校准被同时激励，而不是互相牺牲。优化用直接求导完成，本质上是对软目标的确定性损失函数，「强化」体现在 q̃ 的构造方式上。作者也试过 REINFORCE 估计梯度，没有胜过直接求导。和Multi-Harness RL 把 agent harness 当 RL 环境那条路相比，RLAF 不依赖 rollout 采集，奖励直接来自教师分布和已验证结果，更适合离线、有金标的决策任务。

Drex Max 用的是带 KL 正则的变体：奖励 = 验证结果命中项（ρ·1[a=y*]）+ 裁判对数概率（η·log q^J_a），再减去 β·KL(π_θ ‖ π_0)，π_0 是冻结的 SFT 模型，裁判是 Max 自己基座的生成式形态（同请求做长思维链推理后给出分布），不是更强的模型。裁判的作用是提供一个可以长推理的第二意见，贡献第二分布。消融显示 RLAF 给 Decision Index 带来 +2.0 分、准确率 +1.5 个百分点、ECE 降 0.9 个百分点。

一致性损失项：翻转率从 6.3% 压到 4.2%

指针架构能保证「选项的 key 和选项内容绑定」，但读出头的 Max 不是——选项只靠前缀码（A、B、…）标识，置换选项就改变了哪个 logit 对应哪个选项，顺序鲁棒性完全靠学。所以 SFT 损失里加了两个一致性正则项：

  • 置换一致性 ℓ_π：对选项做随机置换，惩罚预测分布的对称 KL 变化，逼模型对选项排列不变。
  • 状态打乱一致性 ℓ_s：把状态的句子或字段打乱后，惩罚分布变化（stop-gradient 一侧），逼答案不依赖状态的呈现方式。

消融很直接：去掉这两项，Decision Index 分数几乎不变（66.4 vs 66.9），但翻转率（选项顺序改变导致 argmax 改变的决策占比）从 4.2% 升到 6.3%。一致性项不改变准确率，只改鲁棒性。

Drex Max：双向注意力 + 读出头 + 图像编码器

Max 的基座是 Qwen3.8-27B：64 层，48 层 Gated DeltaNet + 16 层全注意力（每第 4 层一个）。关键改动是只在这 16 层全注意力层上去掉因果掩码：DeltaNet 层保持左到右的信息流（4 层里有 3 层），全注意力层里早期 token（状态、选项列表开头）能注意到后续所有 token（选项、指令）。训练出的权重只在用了这个掩码的前向里才给出正确分数——同一套权重走原始因果掩码复算不出同样的打分。

每个问题被编码成一条独立序列：图像 token（ViT 编码后拼在状态前面）→ 状态 → 指令 → 选项（每个选项写成「码: 选项文本」，A、B、…、AA 都是单 token 码）→ 收尾 token <ans>。读出头是一个无偏置线性层 W_r ∈ ℝ^(255×5120)，把 <ans> 处的最终隐状态映到 255 个 logit（每个选项码一个），保留前 K 个做 softmax 就是选项分布。约 130 万参数，和指针头同量级。温度 T = 1.009，在最后一个训练阶段后用留出集拟合，几乎不改变概率。

代价是状态不再可缓存——全注意力层非因果，状态的表示依赖具体问题，每个问题都要重新编码状态。短上下文下差别不大（发布时单请求中位延迟：Max 183ms vs v2.0 151ms vs v1.5 145ms），但长文档多问题时指针模型仍然便宜得多。

三、方法论：从训练到部署

三段训练管线

Max 的训练是三段式。第一段 SFT：全量微调基座加随机初始化的读出头，损失 = 交叉熵（teacher 分布可用则用软标签）+ 平方 Cramér 距离（score 问题）+ 两个一致性项；每个 choice 问题（K≥3）每次看到都打乱选项，随机比例混入「none」或干扰选项，让模型学会「没有合适的选项就不硬选」。v1.5 的第一段更新基座全部权重加指针头。第二段是 Max 专属的 KL-regularized RLAF。第三段训练图像编码器和它到语言模型的投影，教模型从图像做决策。训练数据 1,150,460 条已验证的文本决策记录，横跨 11 个领域，大部分由更强的教师蒸馏，其余来自开源数据集和可验证的程序化数据（执行过的程序、游戏引擎输出），每条标签都对着金标、执行结果或引擎校验过。决策类 benchmark 的样本全部排除，还按「状态精确匹配或共享两条以上 8-词序列」做了污染过滤。

校准：ECE 从 1.4–4.5% 到 0.8–1.4%

每个模型在最终 softmax 前对 logits 施加一个温度。v1.5、v2.0 出厂温度 T=1（不做温度缩放），Max 是 1.009。在约 23 万条决策上测校准：部署温度下 ECE 为 1.4–4.5%，在 Decision Index 样本上重新拟合温度后降到 0.8–1.4%。但分领域、多选项问题上的 ECE 仍偏高，所以单一温度参数不能替代对每个负载的校准监控——置信度阈值能当路由规则用，但前提是知道它在你那个负载上偏多少。

没有解码循环的部署优化

决策模型的推理和语言模型根本不同：没有 decode loop，整个请求落在一次 compute-heavy 的 prefill 里，状态编码一次、所有问题共享。这带来它自己的难点——短请求被 kernel launch 开销主导，长状态吃爆显存，延迟预算紧（决策模型通常挂在另一个系统的请求路径上）。报告里的优化：共享 prefill（8k token 状态、16 个问题、8 并发客户端下吞吐提升 10 倍）、按形状桶录制的 CUDA Graph（把基座和指针头一起录进一张图，单次 launch 重放），以及内核级改动。所有优化按「精确（位级一致）/近似」分类，近似类要单独验证。最终 Max 单请求中位延迟 183ms，每 1000 条决策 $0.06。

四、结果

Decision Index 0.4.1（37 个公开 benchmark，按五个领域加权）：Max 公开套 67.52，全分（含私有子集）66.60，是所对比决策模型中的新纪录，Jev 1.14.0 公开套 60.70。Artificial Analysis 独立跑的 Decision Index 上，Max 在决策模型里第二（64 vs 前三的 65）。Decision Bench v4 上，Max 通过图像编码器直接吃图时准确率 94.0%，与 GPT-6 Sol、d3-turbo 统计上无差异，比 Claude Opus 5.5 低 1.6 个百分点；DecideBench 上决策模型里最高，JevBench-231 上与最强模型相当。Max 在知识领域领先指针模型，但在闭卷知识测试上整体仍落后前沿聊天模型——报告把知识密集型查询路由到其它系统列为后续方向。

消融（Table 7，同一基座、同一训练数据）：SFT only 64.9 → SFT+RLAF（无一致性项）66.4 → SFT+RLAF（含一致性项）66.9 → 加视觉 SFT 66.8。视觉 SFT 段对文本输入无损（66.9→66.8），对纯图像问题把 Decision Bench 60 个图像题的准确率从 63.3% 拉到 98.3%。

对做训练基础设施优化的读者，这篇报告里有两个可迁移的点：一是「恰当评分规则做奖励 + KL 正则到参考策略」这个 RLAF 配方，比 GRPO 类的可验证奖励更适合校准敏感的任务；二是把顺序鲁棒性做成显式的损失项而不是事后测量——如果模型要在生产里被选项排列「打乱」，训练时就该惩罚它。

常见问题

决策模型和自回归 LLM 的选择题，到底差在哪？
自回归模型是「生成文本再解析」：概率来自 token 概率的乘积，选项共享前缀或长度不同时，整串概率的归一化和模型对整个字符串的偏好并不一致，还要逐步重归一化。决策模型是「直接读出分布」：训练目标就是选项集合上的分布，一次前向给出全部选项的概率，输出天然封闭在用户提供的选项集上。

为什么 Max 要每个问题重新编码状态，不干脆也用缓存？
Max 的全注意力层是非因果的——早期 token 能注意到后续 token，状态的表示因此依赖具体问题，无法跨问题共享。这是用成本换精度：双向注意力让所有选项在回答前互相比较、和上下文双向交互，因果指针做不到。短上下文差别不大（183ms vs 145ms），长文档多问题时指针模型仍便宜得多。

翻转率 4.2% 意味着什么？
把选项顺序随机打乱，有 4.2% 的决策里最高概率的选项会换人。这些翻转大多发生在选项多、模型本来就不确定的决策上——模型已经知道自己没把握。报告里一个实用推论：在翻转率高的负载上，拒绝回答「翻转的决策」和拒绝回答「置信度最低的决策」，准确率差不多。

RLAF 里的裁判为什么用 Max 自己的基座，而不是更强的模型？
裁判是 Max 基座的生成式形态（Qwen3.8-27B 高推理模式），和决策版同一个底座，但能以长思维链推理后给出分布。它不是更准的模型，而是一个提供「第二意见」的独立推理者——给没有可验证结果的记录也提供分布。报告诚实指出裁判可能带来的两个副作用：过拟合裁判的偏好、以及让最优策略过度自信，但都未实测。
