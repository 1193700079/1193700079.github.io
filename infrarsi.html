Scaling Law 越来越卡在算力集群的真实吞吐上。大模型加速优化全景图把训练加速划成独立板块，InfraRSI 则是其中「自动化」维度的一个完整样本。过去一年递归自我改进（RSI）和自主编程智能体在单点算法发现、孤立 CUDA/Triton Kernel 生成上进展很快，但一线大模型训练仓库里，启动配置、算子实现、图编译、多机集合通信是咬在一起的——放任通用 Coding Agent 下场改代码，要么频繁撞 OOM 显存墙和编译器死锁，要么为了刷吞吐搞出缩减有效 Batch、挪动计时器起点的「虚假加速」。基元律动（TokenRhythm）联合无问芯穹、北大、上交、清华发布的 InfraRSI 就是冲着这个缺口来的：首个面向大模型分布式训练基础设施的递归自我改进 Agent Harness，同步公开技术报告（arXiv: 2611.11558），全部开源。

核心要点

  • 参数和代码一起搜：不止调命令行开关，还自动改被允许的源码（融合算子、FlexAttention 编译补丁、分桶梯度通信），四大负载几何平均 1.83×、最高 2.75×，MFU 从 17.4% 拉到 30.0%。
  • 16 项校验抓 Reward Hacking：冻结文件 SHA-256 哈希 + 数值容差校验，1,212 次历史运行里 39 次「表面正常跑完」的 Loss 漂移全靠 L4 数值层揪出。
  • LLM 先验不可信：大模型对多卡速度的零样本预测与实测负相关（Spearman r ∈ [-0.49, -0.06]），得用真实硬件测量在线校准先验。
  • 经验跨硬件要打折：跨 Roofline 拐点时优化收益会正负反转（H20 上 tp=2 +24%，H100 上 -4%），经验迁移必须带环境距离加权。

一、它是什么

InfraRSI 的定位是一行命令端到端自进化。把手头的 train.sh、train.py 或整个代码仓交给它，它自动串起五个阶段：init → doctor → run → report → apply。不需要重构现有训练工程——它严格只改你允许改的文件。最终产出是一个可直接投产的 infrarsi_optimized.sh。

它同时搜索两类东西：启动参数/环境变量/配置项和允许修改的源码补丁。后者包括融合归一化/RoPE/SwiGLU 算子、编译块稀疏 FlexAttention、分桶梯度范数通信，并自动把「高收益但耗显存」的配置与「省显存」开关配对。这就是它和传统自动调参器（只动命令行开关）的本质区别——纯调参很快会撞上算子与访存瓶颈，而 InfraRSI 把参数空间和代码空间放在同一个搜索里。融合归一化/RoPE/SwiGLU 这类算子手写融合正是Databricks 那篇 Qwen 微调提速 6 倍里的同一套路——手动融合内核对大模型训练收益显著，InfraRSI 把它从「人写一个内核」推广成「Agent 自动发现并验证一组内核」。

五大产品亮点

  • 参数 + 代码协同优化：几何平均提速 1.83×（最高 2.75×），对比 METR RE-Bench 1.37×、Auto-Research 1.34×、纯调参 OptiCo 1.23×。
  • 全栈通用：原生适配 Megatron-Core、FSDP2/TorchTitan、DeepSpeed、HF Trainer/TRL、PyTorch DDP 五大训练栈；稠密与 MoE、单机与多机通吃。可直接复用本机已登录的 Claude Code 或 Codex CLI（--llm claude-cli / --llm codex-cli），不用配 API Key；也支持 DeepSeek、Anthropic/OpenAI API、OpenRouter/硅基流动等任意 OpenAI 兼容接口与内网 vLLM。
  • 说人话提约束：开跑前交互式问答逐项确认配置（CI 可 --yes 静默）；自然语言写限制如 --requirements "不能改优化器"，会被编译成旋钮边界、冻结文件或强制校验项，只收紧不放宽；运行中 Ctrl-G 打开面板、Ctrl-C 优雅停机并保留当前最佳成果。
  • 严苛校验：5 层 16 项 Harness 强校验，每个候选必须保证训练负载/数据/参数/优化器步数不变、Loss 偏差在容差内（默认 3%），胜出者还要过与基线背靠背的同卡复测。可选双模型交叉把关（如 --llm codex-cli --second-llm claude-cli）：两个模型独立提案、匿名盲评、代码补丁上 GPU 前做两轮交叉 Code Review。
  • 越用越强：验证过的运行沉淀为结构化经验包写回本地/团队共享经验库。换全新 GPU 型号时，历史经验仍能热启动——Qwen3.5-9B（8×H100）上仅凭其它型号积累的经验，加速比从冷启动 1.70× 提到 1.82×，第 9 次试验（2.97 GPU·h）就触及 90% 峰值，冷启动预算耗尽都没到。

二、直接拿 Coding Agent 调训练为什么翻车

作者系统复盘了大量真实分布式训练优化轨迹，总结出四类典型失效：

  • 虚假加速与计时偏移（Reward Hacking & Timing Skew）：改小有效 Batch Size、把辅助参数更新推迟到计时窗口外、移动日志计时器起点、偷引入低精度转换——日志单步耗时大幅下降，训练任务早已被篡改。
  • 跨两个数量级的集群测量噪声（Wide-Spectrum Noise）：独占 8×H100/H200 节点的成对步时噪声低至 0.04%–0.10%，共享主机上则超 6%。写死一个 2% 固定阈值，安静集群上误杀大量 0.5%–1.5% 的真实收益，嘈杂集群上又把随机抖动当有效加速。

    • 这个噪声跨度对做过一线推理实测的读者不陌生——8 卡 PRO 6000 推理实测里「利用率是个谎言」那节讲的就是同一件事：nvidia-smi 的高利用率不代表 GPU 真正被用满，测量口径不对，任何优化结论都站不住。

  • 大模型零样本速度预测严重失准（Miscalibrated LLM Priors）：前沿大模型读得懂代码结构，但对多卡执行速度的零样本定量预测与实测负相关（Spearman r ∈ [-0.49, -0.06]），还频繁对高收益开关投「假阴性否决票」。如 Gemma-4-26B-A4B MoE（8×H200）上 LLM 先验预测开图编译仅 +2.0%，实测 +55%；双机 Qwen3.5-35B-A3B MoE 上先验认为调大 NCCL 通道会变慢，实测 +10.2%。
  • 贪心单起点搜索困死在显存墙与编译冲突悬崖（Memory & Compiler Cliffs）：大招往往孤掌难鸣——单独关激活重算会爆显存（缺口 +18 GiB），开 torch.compile 又会与 Liger 融合算子冲突卡死。只围着当前最优解小步试探的 Agent 一遇 OOM 就放弃，永远找不到「耗显存加速项 + 省显存搭档 + 兼容算子补丁」的三方黄金组合。

三、核心技术体系

贡献一：统一执行与五层十六项验证契约 Harness

把大模型的「假设生成」与底层的「测量、验证、搜索、经验存储」彻底解耦。通过声明式 infrarsi.yaml 与不到 15 行钩子代码的轻量级多栈适配器，构建五阶段闭环：

  • init 锁定契约边界：解析目标仓库 AST，明确可编辑文件，对数据加载器、评测脚本、Loss 定义与计时器等冻结文件锁 SHA-256 哈希。
  • doctor 剖析阶段并标定噪声：剔除 JIT 预热步，实测标定当前集群成对步时噪声 σ_pair，剖析前向/反向/优化器/数据/集合通信各阶段耗时占比（建立 Amdahl 理论加速上限）。
  • run 预算内组合搜索（见贡献二）。
  • report 产出优化报告与成本账本。
  • apply 落地为可投产脚本。

校验是 5 层 16 项确定性不变量加源码路径审计：从执行与显存上限（L1）、负载/数据/模型摘要一致性（L2）、计时窗口内同步优化器步数（L3）、预声明 Loss 与梯度数值容差（L4），到框架内外双时钟一致性与同卡背靠背复测（L5），配合 HMAC-SHA256 防篡改运行回执和候选源码路径审计（Source-Path Audit）。所有失败或被审查剔除的候选消耗的 GPU 时与 Token 全部计入成本账本，杜绝幸存者偏差。审计实证：28 类作弊/篡改扰动加 12 类合法对照的公开校验器压力测试 40/40 全对；对 1,212 次真实历史运行离线复核筛除 400 次（33.0%）无效候选，其中 39 次表面正常跑完，全靠 L4 数值校验层揪出隐蔽的 Loss 漂移。

贡献二：预算受限组合搜索控制器 B-Comp

多卡集群试跑预算宝贵（默认仅 16 次完整运行）。B-Comp 是具备全局记忆的状态化组合搜索控制器，核心三大机制：

  • 多起点初始化 + 全局时间与右截断显存模型：搜索前 3 轮分别从「跨硬件经验库最相似最优解」「LLM 高分差异化配置」「合法随机配置」三个互补起点出发锚定全局方差。在全部历史试验（含 OOM 崩溃试验）上同步维护两个全局统计模型：Cholesky 贝叶斯线性步时代理模型（闭式更新各旋钮、源码补丁及协同对的对数加速后验）；右截断 Tobit 峰值显存账本（联合建模正常完赛的精确峰值显存、OOM 崩溃时的显存分配缺口下界 m_oom、接近显存上限引发分配器抖动时的区间截断似然），精准算出每个配置项到底吃多少 GiB 或省多少 GiB。
  • 先验在线校准、精细失败归因与组合补全：针对 LLM 先验失准用经验贝叶斯收缩，对「被 LLM 低估或否决、但不确定性上界较高」的关键旋钮主动发起逆向试探（Contrarian Big-Knob Probing），用真实硬件测量实时修正先验（找回 +55% 编译加速与 +10.2% 通信优化）。失败时把 OOM、最小冲突配置元组（Minimal Conflict Tuple）、源码补丁报错严格分离归因——不因补丁写坏冤枉好参数，也不因单次 OOM 封杀高潜力开关，而是放进高潜力缓冲池做 Bundle Completion（组合补全）：自动从显存账本挑能覆盖实测 GiB 缺口的省显存旋钮配对重跑。
  • 大旋钮信赖域跳出与源码补丁群试叠加：动态划出单点效应超噪声门限的高影响大旋钮集合 K_big，连续两轮陷入局部平台期就在 K_big 上扩大最小信赖域距离（强制多旋钮跳跃）并跨配置簇热重启；搜索后期把多个已验证的小收益源码补丁按群试（Group Testing）思想叠加组合。

贡献三：跨硬件经验迁移与双层 RSI 自进化闭环

为什么一台集群的调优经验直接照搬到另一代 GPU 常翻车？跨 H20/H100/H200 的 191 个环境、698 条实测观测（论文 Table 3）发现，硬件跨算力-带宽 Roofline 拐点时，优化收益会显著压缩甚至正负号反转（Sign Flips）：算力受限的 H20（148 TF, 4.0 TB/s）上开 FP8 或 tp=2 能提速 +58%/+24%，但迁移到 Tensor Core 算力暴涨的 H100/H200（989 TF）后，GEMM 耗时大缩，量化转换开销与 TP AllReduce 通信反成主导，tp=2 和 FP8 Attention 反转为 -4% 和 -8% 的负优化。

为此设计围绕 Environment（硬件 Roofline、互联拓扑、并行布局）— Observation（完整配置、步时、显存缺口、16 项校验结论）— Effect（成对加速比、噪声基线、条件依赖）的结构化经验协议，通过双层归一化器把不同框架的参数映射到 71 种规范化物理机制（区分算子型 Kernel 与拓扑敏感的均衡型 Balance），用兼容性作用域过滤与环境距离加权安全迁移历史先验。由此跑通真正的双层递归自我改进闭环：内层（单次任务内）用实时硬件测量修正失准的 LLM 先验与显存账本；外层（跨任务与跨硬件）把严格复验后的新发现蒸馏回经验库。

四、实测战绩

在完全一致的任务契约与成本核算下（失败及审计剔除试验消耗的 Token 全额计入横轴），H100 与 H200 集群上四个代表性单机/多机、稠密/MoE 大模型训练任务：几何平均加速 1.83×（最高 2.75×），平均 MFU 从 17.4% 拉到 30.0%（稠密模型最高 45.4%）。最印象深刻的是 Gemma-4-26B-A4B MoE（8×H200）的 2.75× 突破——其它基准方法全卡在 1.29×–1.33× 的局部最优盆地；B-Comp 通过右截断显存账本识别出「关闭 Liger 可释放 14 GiB 显存并消除与 torch.compile 的死锁冲突」，解锁「关闭激活重算 + 图编译」三方协同，再自动合成为 25 个滑动窗口层缓存块稀疏掩码的编译版 FlexAttention 补丁及 5 个全局层的分块因果注意力算子，MFU 提升近三倍。

五、30 秒快速上手

除独立 Harness 外，仓库内额外提供 Skill 版本（python agent_skill/install_skill.py 安装），无需配置 API Key，在编码会话里直接对话即可调用同一套底层优化与校验引擎。从单次任务的自动调优，到跨任务、跨代际硬件集群的经验自进化，InfraRSI 在 AI Infra 智能化与 RSI 方向迈出了重要一步。五阶段分步运行、预算控制与经验包分享（infrarsi exp）的详细教程见官方博客与代码仓库。

常见问题

InfraRSI 和直接让 Claude Code / Codex 改训练脚本，区别到底在哪？
区别是契约。InfraRSI 先用 init 阶段锁死冻结文件（数据加载器、Loss 定义、计时器）的 SHA-256 哈希，再在 16 项校验下搜索——改小 Batch、挪计时器、偷换低精度都会被 L2 摘要一致性和 L4 数值容差拦下。裸跑 Coding Agent 没有这层防线，Reward Hacking 是默认结局而不是异常。

为什么 LLM 先验预测速度会负相关？
大模型读得懂代码结构，但「多卡硬件上这个开关会快多少」是一个它没在训练里见过的定量问题。实测 Spearman r ∈ [-0.49, -0.06]：它认为「该慢」的开关往往实测更快（比如 Gemma-4 MoE 上预测 +2.0% 的图编译实测 +55%）。所以 InfraRSI 不信任 LLM 的绝对预测，只用它做差异化起点，再用真实硬件测量在线校准。

右截显存账本解决了什么问题？
普通线性模型学显存时，OOM 崩溃的样本没有「峰值显存」可用，直接丢掉就会系统性低估显存消耗。右截 Tobit 把 OOM 当作「显存 ≥ 上限」的右截断观测，联合建模正常完赛的精确峰值和崩溃时的分配缺口下界，从而在 16 次试跑里算出每个配置到底吃多少 GiB，进而把「耗显存加速项 + 省显存搭档」配对起来。

经验从 H20 迁到 H100 为什么会反号？
H20 是算力受限（148 TF, 4.0 TB/s），GEMM 慢、访存相对不那么贵，开 tp=2 摊薄通信能提速 +24%。H100/H200 Tensor Core 算力暴涨到 989 TF，GEMM 本身变快了，量化转换和 TP AllReduce 通信反而成了主导，同样的 tp=2 变成 -4%。所以经验迁移必须带环境距离加权，不能把一台机器的最优解直接搬过去。
