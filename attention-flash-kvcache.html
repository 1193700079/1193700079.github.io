大模型面试里 Attention 这块，翻来覆去就考两道题：训练阶段为什么用 Flash Attention，推理阶段 KV Cache 是怎么回事。一个解决训练慢、显存爆，一个解决推理重复计算。这篇把两题各自的原理一次讲透。

一、原始 Attention 的麻烦

vanilla attention 的时间和空间复杂度都是 O(N²)，N 是序列长度。序列一变长，两个麻烦同时出现：

  • 速度慢，N² 直接卡训练吞吐
  • 中间那张 QK 分数矩阵（N×N）必须整个存在显存里，序列一长显存就爆

Flash Attention 的动机就是针对这两点：加速计算，减少显存占用。要理解它怎么做，得先看 GPU 的存储层级。

二、HBM 和 SRAM 的层级

HBMSRAM
是什么高带宽显存（GPU 主显存）片上静态随机存取存储器
容量约 40GB约 20MB
速度慢快十几倍

原始 attention 的做法是：把 Q、K、V 从 HBM 读出来，算出整个 N×N 的分数矩阵，写回 HBM，再算 softmax，再写回 HBM，再乘 V。数据在 HBM 和计算单元之间反复搬运，瓶颈不在算，在搬运。

Flash Attention 的思路：把 Q、K、V 按块切分，每次取一小块从 HBM 加载到 SRAM，在片上把这块的 attention 算完，再把结果更新回 HBM。搬运量从 O(N²) 降到 O(N²/块大小)，而且块在片上循环使用，HBM 读写次数大幅下降。

三、softmax 的平移不变性

分块计算有一个绕不开的问题：softmax 的分母需要对所有块求和，但分块计算时手里只有当前块的分数。怎么办？

靠 softmax 的平移不变性：分子分母同时减去同一个常数 β，等式不变：

softmax(x) = softmax(x − β)

工程上算 softmax 时本来就习惯先减去最大值，保证数值稳定。那问题就变成：怎么在分块计算的前提下，用每块的局部最大值表示出全局的最大值。

推一下。设全局向量 x 的下标从 1 到 B1+B2，切成两段：第一段到 B1，第二段从 B1+1 到 B1+B2。记 M1、M2 为两段的局部最大值，M 为全局最大值。全局 softmax 的分母是：

Σ(1→N) exp(xᵢ − M)

把求和拆成两块，每块加上再减去自己的局部最大值：

Σ(1→B1) exp(xᵢ − M1) · exp(M1 − M) + Σ(B1+1→N) exp(xᵢ − M2) · exp(M2 − M)

这个等式恒等成立。关键在于：每块的求和项 只需要本块的局部最大值，块间合并时只需要比较局部最大值、修正一个 exp(Mi − M) 的因子。全局值完全可以由分块结果逐步合并出来，这就是 Flash Attention 能在线分块计算的数学基础。

四、KV Cache 是什么，怎么走

KV Cache 用在推理阶段，动机是优化推理性能、支撑更长文本。要理解它，先看 decoder-only 模型的自回归特性。

生成是逐 token 的：生成第 t 个 token 时，它的输入要拼接之前所有时刻的输入和输出。而 self-attention 的主要计算量在 QKV 这一部分——每个时刻都要对之前所有 token 的 K、V 重新算一遍，产生大量重复计算。

KV Cache 的思想就是空间换时间：把每个时刻算出来的 K 和 V 缓存下来，下次直接用，不重算。

具体走两阶段：

  • 预填充阶段（prefill）：生成第一个 token 时，手里只有输入、还没有任何生成 token，此时 KV Cache 为空，要为每个输入 token 在每一层 Transformer 生成一份 KV 存入缓存。
  • 生成阶段（decode）：从第二个 token 开始，每步做两件事：一，用当前 token tᵢ 乘 W_K 更新 K 的缓存、乘 W_V 更新 V 的缓存；二，用当前 token 的 query（tᵢ·W_Q）算下一个 token——q 乘 K 的转置、除以维度开方、softmax、再乘 V、再乘 out 矩阵（多头汇总），加上残差连接得到 t_{i+1} 的 attention 输出，再过 FFN（W1、W2 两个矩阵加激活，同样带残差连接），得到下一个 token 的表示。

五、为什么没有 Q Cache

这是高频追问：既然 K、V 都缓存了，为什么 Q 不缓存？

因为每个 token 在生成时只用到当前这一个 Q。看 mask 的作用：decoder-only 是自回归结构，生成当前 token 时看不到后面的 token，所以 QK 分数矩阵要做 causal mask——mask 之后是一个下三角矩阵。算第 4 个 token 时，只取第 4 行乘 V，用到的 Q 只有 Q₄，但 K 和 V 要用到 K₁~K₄、V₁~V₄ 全部。

结论：K、V 的信息被后续所有 token 反复使用，必须缓存；Q 每个时刻只被自己用一次，缓存没有意义。所以只有 KV Cache。

六、KV Cache 占多少显存

显存公式：

KV Cache 显存 = 序列长度 × batch size × 2（K 和 V 各一份）× n_heads × d_head × layers × 2（字节，fp16 每值 2 字节）

注意两点：

  • layers 是层内 KV Cache——每一层 Transformer 都各自占一份，层数多就线性放大。
  • 存储一般是 float16，每个数占 2 字节。

从这个公式能直接看出问题：模型大（layers 多）、head 维度大、序列长、batch 大，任何一个因素上去，KV Cache 的显存都会变得非常大。于是就有了 MQA 和 GQA。

七、MQA 和 GQA

动机很朴素：KV Cache 是空间换时间，缓存太大就是负担，得想办法缩小。

  • MHA（多头注意力）：每个 query head 对应一份独立的 K、V，缓存量最大。
  • MQA（Multi-Query Attention）：所有 Q head 共享一份 K、V。缓存最小，但效果有明显折损——实验确认折损真实存在。
  • GQA（Grouped-Query Attention）：折中方案。把 Q head 分成多个组，每组共享一份 K、V。既减少缓存占用，又保住效果。

目前较新的模型（包括 Qwen2 这一代）普遍采用 GQA。
