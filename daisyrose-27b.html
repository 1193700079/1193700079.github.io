DaisyRose-27B 是 RadixArk 的第一个开源模型：一个多模态推理模型，底座是 Qwen3.8-27B，但后训练只用了强化学习——没有监督微调（SFT）、没有从更大的模型蒸馏。约 1,200 个精挑的长程 agent 任务、会话最长 1M token、144 张 H200 训了 18 天，把 Terminal Bench 4.1 的 pass@1 从 5.6 拉到 12.0，图像理解、tokenizer、chat template 和 256K 上下文全部原样保留，是 Qwen3.8-27B 的即插即用替换。权重 Apache-2.0 开放，BF16 / FP8 / NVFP4 三种精度，社区量化生态也已经齐了。

DaisyRose-27B 是什么

先定位：它是多模态的（image-text-to-text），能读图；底座是 Qwen3.8-27B，保留了底座的图像理解能力和 256K token 上下文。架构、分词器、chat template 都不动，所以任何跑过 Qwen3.8-27B 的推理栈、后训练栈，把它当 drop-in 替换就行。参数量 BF16 下约 27.78B（27,781,427,952）。

真正的差异点在后训练方式：它只靠强化学习，既不 SFT、也不蒸馏。下面一节展开。

纯 RL 训练：没有 SFT，也没有蒸馏

官方给的训练配方很直白：在约 1,200 个精心挑选的长程（long-horizon）agent 任务上跑强化学习，会话最长 1M token，144 张 H200 训了 18 天。

  • 没有 SFT：不做任何监督微调。也就是说它没有从人工标注或指令对里"背答案"，能力全部来自 RL 的环境反馈。
  • 没有蒸馏：不是从某个更大的老师模型抄行为。这很重要——纯 RL 不会被"蒸馏天花板"卡住，模型的上限不依赖于任何老师。
  • 长程 agent 任务：训练目标是终端操作、多步推理这类长链路 agent 任务，这正是 Terminal Bench / SWE 系列考的东西。会话最长 1M token，意味着它是在超长上下文里学规划的。

结果是 Terminal Bench 4.1 的 pass@1 从底座的 5.6 涨到 12.0——翻倍还多，而且只是纯 RL 的功劳，没有任何蒸馏或 SFT 的"外援"。这是它最值得讲的一点：证明了 RL-only 路线在长程 agent 能力上的真实增益，而不是靠蒸馏或指令对堆出来的。

两个读法：一，对底座全面小幅领先（Terminal Bench 4.1 5.6→12.0 最猛，其余编码/推理/指令遵循普遍涨几个点）；二，对更大的模型，在 Terminal Bench 4.1 这类长程任务上，它和 Inkling 2 Small（13.0）、GPT-6 Luna（15.2）处在同一量级，但底座参数只有 27B——纯 RL 的增益在这里体现得最清楚。

官方还说明：DaisyRose-27B 的分数取 BF16 和 FP8 两次运行里更高的那个，两个精度在跑过的所有基准上差异都不到 1 分；推理参数用底座的推荐 thinking-mode 设置（temperature 1.0、top_p 0.95、top_k 20、reasoning effort xhigh、256K 内不设 max_tokens）。

即插即用替换

它刻意保留底座的架构、分词器、chat template，以及图像理解和 256K 上下文。这意味着：

  • 现有跑 Qwen3.8-27B 的推理服务，换权重即可，prompt 格式、tokenizer、上下文长度都不用改。
  • 后训练栈里把 base model 换成它，模板兼容性不变，可以直接继续 SFT / RL。
  • 多模态（读图）能力随底座保留，不是纯文本模型。

这是它和很多"基于某底座改架构/换 tokenizer"的衍生模型最大的区别——零迁移成本。

怎么跑

vLLM（NVIDIA，BF16 / FP8）：

开 thinking 模式就按底座推荐参数：temperature 1.0、top_p 0.95、top_k 20、reasoning effort xhigh。

GGUF + llama.cpp / Ollama（本地 / 端侧）：

显存不够就上 NVFP4（NVIDIA）或 MLX oQ4h-mtp（Apple Silicon）。
